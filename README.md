# lalitasahasranama.com

The 1000 names of Śrī Lalitā, one page per name, with meaning in layers (word by word,
explanation, inner meaning, story and commentary), audio, and the names in ten Indian scripts.
Built with [Astro](https://astro.build) as a static site.

## Run it

Needs Node.js 22.23.4 or newer (Astro 7 refuses older versions). With nvm, `nvm use` picks the
version in `.nvmrc`.

```bash
nvm use
npm install
npm run dev        # http://localhost:4321
npm run build      # checks content, then writes the site to dist/
npm run preview    # serves dist/ locally
```

## How it is organised

- **Content** lives in `content/`: one JSON file per name (`content/names/0001.json`) and
  `content/verses.json`. Nothing about the names is written in code.
- **Only Devanagari is stored.** Telugu, Tamil, Kannada, Malayalam, Bengali, Gujarati, Odia and
  IAST are generated by `src/lib/translit.mjs`.
- **Pages**: English at `/name/4-chidagni-kunda-sambhuta/`, Hindi at `/hi/name/4-chidagni-kunda-sambhuta/`,
  plus a page per verse (`/verse/1/`), a list of all names (`/names/`) and `sitemap.xml` with hreflang links.
- **Other languages** (Telugu, Tamil and the rest) are readable on every page through the
  language buttons. They get their own pages once their content is written: see AGENTS.md.
- A name gets a page in a language only when **every layer** is written in that language,
  so thin, half-translated pages never reach Google.

## Content status

All 1000 names are written in English and Hindi, every layer, as **drafts**. Claude wrote them
from the master text (stotranidhi.com) and Bhāskararāya's *Saubhāgya Bhāskara* (Sanskrit
Wikisource edition). Each commentary quote was checked by machine, word for word, against that
edition. No scholar has reviewed them yet, so every page shows a draft notice.

- `content/TEXT-NOTES.md` lists the sources, variant readings and corrected archana forms.
- Each name file's `review.notes` lists what a scholar should check for that name.
- After review, set `"review": { "status": "reviewed", "reviewedBy": "…" }`.

`AGENTS.md` is the brief for a coding agent (Claude Code, Codex or others). Use it to add
other languages or correct names, one verse or a small batch at a time.
`npm run validate` prints how many names exist and how complete each language is.

## Audio

Put recordings in `public/audio/`, for example `public/audio/chant/0004.mp3`, and set
`"audio": { "chant": "/audio/chant/0004.mp3", "slow": "/audio/slow/0004.mp3", "archana": "/audio/archana/0004.mp3" }` in the name file.
Until a name has recordings, its buttons use the visitor's device voice for Hindi, where available.

For human Sanskrit recording sessions, run `npm run audio:prepare` (or append `-- /path/to/output`).
It generates a recording brief, a numbered transcript and a JSON manifest directly from all
1000 name files. Start with the first ten names for pronunciation review, then record the
remaining names. The generated pack does not publish recordings or change any name content.

## Deploying

Any static host works (Cloudflare Pages, Netlify, Vercel, GitHub Pages): build command
`npm run build`, output folder `dist`. "Today's name" uses a shared shuffled order of all
1000 names and changes at midnight India time. The browser keeps the featured name, meaning,
archana, pronunciation and link current without daily rebuilds, including when a page stays
open overnight. It fetches only the selected name's small static JSON file. Without JavaScript,
the home page retains the name selected when the site was built.

Every public HTML page has explicit `index, follow` robots metadata, canonical and language
alternate links, Open Graph tags and Twitter card tags. The 404 page uses `noindex, follow`.

`vercel.json` is set up for Vercel: it redirects `/name/x` to `/name/x/` so Google sees one address
per page, and lets browsers keep the fonts, CSS and scripts in `/_astro/` for a year. Elsewhere,
set the same two things in that host's settings.

The Vercel project is **lalita-sahasranama** in the **Cosmos** team, connected to this
repository's `main` branch. The primary address is `https://www.lalitasahasranama.com`;
the root domain redirects to it permanently. DNS is managed at Spaceship, with the
project-specific A and CNAME records provided by Vercel.

Google Search Console uses the **lalitasahasranama.com** Domain property under
`illumind.software@gmail.com`, which covers both the root and `www` addresses. Keep its
verification TXT record in Spaceship. The sitemap is
`https://www.lalitasahasranama.com/sitemap.xml`; `public/robots.txt` also advertises that URL.

Google Analytics uses the **Lalita Sahasranama** GA4 property in the **Illumind Software LLP**
account (`illumind.software@gmail.com`), with property ID `565436143`, web stream ID
`16390848991` and measurement ID
`G-KZNP849N20`. The tag lives in `src/components/GoogleAnalytics.astro`, included by the shared
layout. It sends data only from the production hostname, so localhost and Vercel preview
deployments do not affect the reports. Reporting uses India Time and INR.

## Fonts, icons and the share picture

Fonts come from the `@fontsource` packages and are served by the site itself (`src/styles/fonts.css`).
The share picture shown by WhatsApp, Facebook and X (`public/og-image.jpg`) and the icons
(`favicon.ico`, `apple-touch-icon.png`, `icon-192.png`, `icon-512.png`) are drawn by
`node scripts/make-images.mjs`, which needs Google Chrome. Run it again after changing the design.
